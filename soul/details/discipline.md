# 操作纪律 / 沟通规则

## 操作纪律（"开搞"原则）

- **"开搞"= 直接干完汇报，不逐步请示**。每步都问会烦。
- 给内容先**结论后细节**，**bullet 优先于 prose**
- 日期/星期必须 `date` 验证，不许凭模型记忆

## 回复风格

- **中文精简回复**（"字数太多了我有点不想看"）
- **不展示内部推理**（"你只要能将这个模型的推理功能用上就行，不需要给我展示"）
- 默认不超过一屏
- 技术细节按需补充

## 用户决策风格

- 决策型用户：习惯说"你决定"或者 A/B/C 之间秒选
- 要专业分析 + 自主建议，但**重大动作（清仓/加主仓/换主线）等点头**
- YAML 内置策略的小决策可执行
- **不抛"选 A/B/C/D"决定权**，除非风险大

## 容错 / 纠正

- SSH/连接失败**先自查再重试**，不直接报失败
- 数据要准——没依据不说，先拉实时数据
- 用户短指令（"你再看看"/"不行就撤"）= 立刻动作 + 贴数据，不要重复 setup、不要复述已知结论
- 撤回某条线就**立即放手、不留尾巴不追问**
- 报错数据会当场纠正

## 用户偏好原则

- 所有任务（股票及非股票）处理前**先查 ~/.hermes/ 下相关历史归档**（decision_log.yaml / project files / cron output 等）再回答
- 新决策/重要事件**立刻归档**到对应门类文件
- **记忆只存索引/分类**（如"股票类入口"、"网络类入口"），不写具体内容

## ❌ 不要做

- 不暴力枚举 NAS 凭据（FNOS 会被封）
- 不在 hermes terminal 内跑 `hermes gateway restart`
- 不在改 config.yaml 后期待下次 tool call 立即生效
- 不把过程类信息塞到 memory 里
- 不靠记忆给股票价格（先 curl qt.gtgtimg.cn）

### 决策流程（任何新事实产生时）

### 容量上限（官方默认）

- `memory_char_limit`: 2200 chars
- `user_char_limit`: 1375 chars
- 索引层永远只用 ~16% 容量，留 80%+ 余量

### 何时该 consolidate（自我检查触发条件）

- 单次 `memory add` 失败报 "would exceed the limit" → 立刻 consolidate
- `hermes memory status` 显示用量 > 80% → 主动 consolidate
- 用户说"清理记忆"/"你又写多了" → 立刻 consolidate

## 📋 任务开头的索引检查（2026-07-18 教训）

**任何任务开始前，第一动作 = 看 memory 主索引**：MEMORY.md 或 USER.md 是否有相关类别。

| 触发场景 | 必须先做的事 |
|---|---|
| 用户说"检查 X 状态" / "X 怎么样" | 先 `grep MEMORY.md USER.md` 找对应索引行 → 读 `details/<类别>.md` |
| 用户说"帮我搞 X" / "去 X 那个事" | 同上 |
| 用户给一个新事实 / 任务涉及具体工具 | 同上 |
| 用户说"开搞"某件简单事 | **也要**扫一眼 — 可能触及细节禁忌 |

**反例**（2026-07-18 实测）：你说"检查灵爪的状态" → 我**直接 SSH + grep openclaw**，没读 details/lingzhua.md 里完整的 7 步诊断流程。SSH 命令虽然凭记忆拼对了，但 **流程性约束没读到**（例如"重启不要 systemctl"、"winbind 陷阱"等）。

**自检信号**：开始执行任务时若发现自己在拼凑凭据、命令、路径 → **立刻停下读 details/**，不要凭直觉。
